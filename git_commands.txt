GIT COMMANDS USED IN MY PROJECT

Each entry gives the command as I typed it, followed by a short note on why
I ran it and at which step.


1. SETTING UP THE REPOSITORY
----------------------------
git init -b main
    Turned my website folder into a Git repository, with "main" as the
    first branch. (Step 1)

git branch --show-current
    Quick check that I was on "main" straight after git init. (Step 1)


2. STAGING AND COMMITTING
-------------------------
git add <file>
    Put a changed file into the staging area so the next commit picks it up.
    I used it on index.html, about.html, .gitignore and this file.

git commit -m "<message>"
    Saved what was staged as a commit. My messages, in order: "Initial project
    setup", "Update homepage content", "Add feature page content", "Add
    .gitignore for log files and temp folder", "Add useful resources section to
    homepage", "Add Git command reference", "Add contact section to about page",
    "Update Git command reference".

git diff --stat
    Counted the lines I had changed in index.html before staging the second
    commit (it showed 16 new lines).

git diff --cached --stat
    Proved that, after the soft reset, my 9 new lines were still staged.


3. WORKING WITH BRANCHES
------------------------
git branch feature
    Made the "feature" branch at the same point as main.

git checkout feature / git checkout main
    Moved between the two branches - to feature for the About page edit,
    then back to main for the merge.

git branch
    Listed my local branches; the * marks the one I am on.

git branch -M main
    Made sure the branch was named "main" right before the first push.

git branch -vv / git branch -r / git branch -a
    After pushing: which remote branch each local branch follows, the remote
    branches only, and everything together.


4. MERGING
----------
git merge --no-ff feature -m "Merge branch 'feature' into main"
    Brought the feature work into main. I added --no-ff so Git would make a
    real merge commit and the branch would still show up in the graph.


5. CHECKING STATUS AND HISTORY
------------------------------
git status
    Ran this before and after almost every step to see what was modified,
    staged or untracked.

git log --oneline
    One line per commit on the current branch - handy after each commit.

git log --oneline --graph --all
    Drew both branches as a graph so the split and the merge are visible.


6. IGNORING FILES
-----------------
.gitignore contains two rules:  *.log   and   temp/

git check-ignore -v debug.log error.log temp/notes.txt
    Told me which line of .gitignore matched each of my three test files.

git status --ignored
    Listed the ignored test files, confirming none of them were tracked.
    (I deleted the test files afterwards; they were never committed.)


7. UNDOING COMMITS
------------------
git reset --soft HEAD~1
    Took my "Add useful resources section to homepage" commit (523a07d) off
    main but kept its changes staged, so I could simply commit them again.

git revert --no-edit HEAD
    Undid "Add contact section to about page" (bf5012b) by adding a new commit
    (65dbd78) with the opposite change, so the undo is visible on GitHub.

Why both? reset --soft rewrites my own local history and is only safe before
pushing; revert keeps the history and is the safe choice once work is shared.


8. CONNECTING TO GITHUB
-----------------------
git remote -v
    Showed which remote URL my repository pointed to, before and after the
    change.

git remote remove origin
    Deleted an old remote entry that pointed to a repository I no longer use.

git remote add origin https://github.com/RashiMalik02/github_sga.git
    Linked my local repository to github_sga, which I created on GitHub after
    all of the local commits above already existed.


9. PUSHING AND CHECKING THE REMOTE
----------------------------------
git push -u origin main
git push -u origin feature
    Uploaded both branches; -u remembers the remote branch for later pushes.

git push
    Sent my last commit on main, using the upstream set by -u.

git ls-remote --heads origin
    Asked GitHub directly which branches it holds; the commit IDs matched mine.
